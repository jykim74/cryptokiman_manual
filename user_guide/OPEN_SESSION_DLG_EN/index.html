    Open Session Dialog

    This guide describes the Open Session dialog implemented by open_session_dlg.cpp, open_session_dlg.h, and open_session_dlg.ui.

    Purpose

    Use this dialog to open a PKCS #11 session on the selected slot. A session is needed for most token operations, including logging in and working with objects.

    Fields and options

    Control Description
    Slot Info Read-only information identifying the selected slot. The slot is chosen in the main window before opening this dialog.
    CKF_SERIAL_SESSION Requests a serial session. This option is checked by default.
    CKF_RW_SESSION Requests a read/write session. This option is checked by default. Clear it to request a read-only session.

    The two checkboxes set PKCS #11 session flags. A read/write session permits operations that modify token objects when the token and user permissions allow them. A read-only session does not request write access.

    Buttons

    Button Description
    WaitForSlotEvent Calls the module's slot-event function and displays its return code.
    OpenSession Opens a session with the selected slot and flags. On success, the session is recorded in CryptokiMan and the dialog closes. On failure, an error is shown and the dialog stays open.
    Close Closes the dialog without opening a session.

    The button is labeled WatiForSlotEvent in the current UI source; it is intended to refer to WaitForSlotEvent. The exact result and whether the call waits depend on the Cryptoki module implementation.

    Typical use

    1. Select the desired slot in the main window.
    2. Choose Module > Open Session.
    3. Keep or change the session flags as needed.
    4. Select OpenSession and check the Information or Log area for the result.
